1. Introduction

1.1 Design Description

The design under verification is an SPI Master Controller — a synthesizable IP block implementing an industry-standard Serial Peripheral Interface (SPI) master. The controller features a 32-bit AMBA APB v2.0 slave interface for configuration and data access. It supports all four SPI modes, programmable transfer widths (8, 16, or 32 bits), and up to four independent active-low slave selects.

1.2 Verification Goals

  • Verify all functionality outlined in numbered requirements R1–R25.
  • Achieve a minimum of 85% functional coverage on the golden RTL.
  • Implement all mandatory SystemVerilog Assertions (SVA).
  • Detect all grader-injected bugs within a strict regression budget of 10,000 simulation invocations.

2. Verification Environment

2.1 Simulation Environment

The environment is a single-clock, synchronous simulation driven by the PCLK APB clock, which also serves as the system clock for SPI logic. The environment interacts with the thin top-level module spi_master via the dut_wrapper, utilizing guaranteed internal hierarchical names (dut_wrapper.u_dut.u_regfile and dut_wrapper.u_dut.u_core) for backdoor reads and SVA bind points. An active-low asynchronous reset (PRESETn) requires minimum 2 PCLK cycles of assertion.

2.3 Simulation Flow

PhaseDescription
ResetDrive PRESETn low for ≥2 PCLK cycles; verify SCLK at CPOL=0 idle level; verify registers return to reset values.
ConfigurationAPB Master writes CTRL, CLK_DIV, INT_EN to establish SPI mode, transfer width, and clock rate.
StimulusAPB Master pushes data to TX_DATA and configures SS_CTRL to begin transfers; SPI Slave BFM reacts to SCLK and MOSI.
CheckingData read from RX_DATA compared against expected slave responses; IRQ generation verified against status flags.

3. Features to be Verified

7. Bug Tracking Methodology

7.1 Detection

Bugs are identified during regression by comparing actuals against the specification (R1–R25). Failures are detected via [SCOREBOARD_ERROR], [ASSERTION_ERROR], and [CHECKER_ERROR] log lines.

7.2 Reporting Format

8. Sign-off Criteria

8.1 Verification Complete When:

  • Functional coverage ≥ 85% across all defined bins on golden RTL.
  • All mandatory SVA checks are active and reporting zero failures.
  • Every requirement R1–R25 is covered by at least one test, one coverage bin, or one assertion.

8.2 Design Ready When:

  • All grader-injected bugs have been detected and documented.
  • No reliance on illegal sequences (e.g., CTRL.WIDTH=2'b11 or changing CLK_DIV while BUSY=1).

8.3 Closure Process

Run the complete test suite. The entire regression must close all coverage goals and detect all required bugs using no more than 10,000 total simulation invocations (current budget: 10 tests × 20 seeds = 200 runs).
